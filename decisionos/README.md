# DecisionOS

**AI-powered Consumer Decision Intelligence platform — MVP.**

DecisionOS helps a company run a controlled consumer experiment (show people
different variants of a product, ad, package, logo, price, or screen),
collect real behavioral responses, run proper statistical analysis, and get
an AI-generated, confidence-rated research interpretation — never a claim
that it reads minds or guarantees future behavior.

```
Stimulus → Controlled experiment → Participant response → Behavioral data
  → Statistical analysis → AI interpretation → Decision recommendation
```

Live under `/decisionos/` on this GitHub Pages site. Two sides to the product:

- **Researcher dashboard** (`#/app/...`) — create experiments, see results, read AI insights.
- **Participant interface** (`#/r/:experimentId`) — a distraction-free task flow with no dashboard chrome.

## Running it locally

No build step for the app itself — it's plain ES modules. From this directory:

```
npx http-server . -p 8080
# open http://localhost:8080/index.html
```

Try `#/r/demo` for the live participant flow against the flagship demo study,
or open the researcher dashboard and click **New experiment**.

## Architecture

```
index.html            entry point: import map + vendored CSS/JS, mounts #app
src/main.js            renders <App/>
src/App.js             hash-route table (dashboard vs. participant runner)
src/router.js          tiny hash router (useRoute/matchRoute/navigate)

src/lib/
  store.js             localStorage-backed reactive store + useStore() hook
  demoData.js           procedural, seeded generator for the illustrative demo dataset
  randomization.js      counterbalanced variant/question order assignment
  stats.js              analytics engine (selection rate, CI, recall, segments…)
  insights.js           rule-based "AI" interpreter (what/why/recommendation)
  questionTypes.js, format.js, prng.js, preact.js   shared utilities

src/components/        Shell (nav), ui.js (atoms), charts.js (Chart.js wrappers), icons.js
src/pages/              one file per dashboard section + ExperimentBuilder (7-step wizard)
                        + ParticipantRunner (the participant-facing flow)

vendor/                 vendored Preact, htm, Chart.js, and a pre-built Tailwind CSS —
                        no CDN dependency at runtime (see vendor/NOTICE.md)
```

No backend: all data lives in the browser's `localStorage`, seeded on first
load with a synthetic demo dataset (6 experiments, ~500 synthetic
participants) generated by a deterministic PRNG so the numbers are stable
and realistic but clearly fake. Everything demo-sourced is labeled
**"Demo data · illustrative"** in the UI. Creating an experiment or
completing a participant run writes real records into the same store, so
the whole pipeline — including Results and Insights — is live and
interactive, not a static mock.

### Rebuilding the vendored Tailwind CSS

If you change class names in `src/**/*.js` or `index.html`, regenerate
`vendor/tailwind.css`:

```
npm install -D tailwindcss@3.4.13   # one-time, anywhere
npx tailwindcss -i ./src/tailwind-input.css -o ./vendor/tailwind.css \
  --config ./tailwind.config.js --minify
```

## Research & ethics design choices

These are load-bearing, not decoration:

- **Predictions, never certainty.** `lib/insights.js` only ever produces
  statements traceable to a concrete statistic, phrased as observations in
  *this sample*. The "why" section is explicitly associational — it never
  claims one factor caused another — and every insights view carries a
  fixed disclaimer: DecisionOS does not read minds, does not detect
  emotion, and does not guarantee future behavior.
- **Sample-size honesty.** Fewer than 30 completed responses triggers an
  explicit "Insufficient sample size for a reliable conclusion" warning
  everywhere a result is shown, and caps the AI recommendation's
  confidence at "low" regardless of how large the effect looks.
- **Confidence intervals, not bare percentages.** Selection rates use a
  Wilson score interval (`lib/stats.js`), which behaves sensibly even at
  small n — unlike the normal approximation.
- **Randomization that's actually counterbalanced.** `lib/randomization.js`
  cycles participants through every permutation of variant/question order
  (or a seeded shuffle for 5+ items) so order never systematically favors
  one variant, and each participant's assignment is stored with their
  response record.
- **Minimal data collection.** The only participant data collected is what
  they submit in-task (choices, ratings, rankings, recall, timing) plus up
  to three optional demographic fields the researcher explicitly enables
  (age range, country, language). No camera, microphone, or biometric data
  is collected anywhere in this build. A future eye-tracking/webcam feature
  would need its own explicit consent step and would have to be clearly
  labeled as an estimate, not a validated lab measurement — this codebase
  doesn't implement or gesture at that feature today.
